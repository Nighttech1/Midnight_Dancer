# Midnight Dancer — продолжение с другого компьютера

Контрольная точка: 19 ноября 2026. Репозиторий: https://github.com/Nighttech1/Midnight_Dancer

## Что запускать завтра

1. Открыть этот репозиторий, ветку `checkpoint/2026-11-19-accepted-source`. Не выбирать устаревшую `main`, пока checkpoint не влит.
2. В Codemagic открыть уже существующее приложение `Midnight_Dancer`, подключённое к этому репозиторию. Выбрать эту же ветку и прочитать корневой `codemagic.yaml`.
3. Для первой проверки KMP выбрать **`ios-ipa-kmp`**. Это **неподписанная Debug-сборка для диагностики компиляции**, не установка через TestFlight. Не выбирать `ios-ipa-full/lite/standard/english`: это прежний Flutter-проект.
4. Запустить сборку вручную. Исходники, Gradle wrapper, iOS splash и скрипт сборки находятся в GitHub; подключение к прежнему Windows-компьютеру не требуется.
5. Сохранить ссылку на запуск, commit SHA, название упавшего шага и первую содержательную ошибку. Диагностические логи брать из артефактов Codemagic. Перед передачей логов удалить токены и другие секреты, если их добавили вручную.
6. Новый агент сначала читает `AGENTS.md`, этот файл и `docs/checkpoints/2026-11-19/STATUS.md`; затем проверяет конкретный commit/логи, оформляет тикеты и продолжает цикл. Не считать исторические отчёты свежими запусками.

Автоматические запуски текущих KMP workflow отключены в этом checkpoint: завтра запускать вручную. Облачные минуты сегодня не расходовали. Для первой компиляции Apple-ключ не нужен.

## Состояние продукта

- Рабочий продукт: `kmp/` (Kotlin Multiplatform, Android Compose, iOS SwiftUI). Flutter-код сохранён как история, он не является текущей Android-версией.
- Принята Android beta с единым каталогом стилей, защищённым «Без стиля», приватным хранением импортированного медиа, обменом сетами, Free/Pro-политикой и частью хореографии. Это не подтверждение коммерческого релиза или реальной оплаты подписки.
- Текущая iOS-оболочка ещё не имеет подтверждённого соответствия Android. Нужны production bootstrap/DI и постоянное хранилище, медиапути/AVFoundation, сценарии интерфейса, жизненный цикл, обмен и миграция данных прежней Flutter-версии. Прочитать реализацию, не обещать готовность по одному наличию IPA.
- Новую iOS-компиляцию на macOS в этой контрольной точке ещё не выполняли. Свежую Android-приёмку тоже не повторяли: перенесён ранее принятый исходный код.

## Где доступы, и чего нет в Git

В интерфейсе Codemagic подтверждены: нужный GitHub-репозиторий подключён через аккаунт Nighttech1; Developer Portal показывает два существующих подключения, в том числе **Midnight Dancer**. Секретные значения не читались, не копировались в Git и не создавались заново. Успешный запрос к Apple API с этими ключами ещё не проверен; «connected» означает сохранённую настройку, а не гарантию её работоспособности.

Для следующего агента:

- Войти в собственный Codemagic через интерфейс. Сессию этого компьютера и пароль из чата переносить нельзя. Владелец должен иметь возможность войти с другого устройства и пройти проверку входа.
- Для подписанной сборки использовать существующую **Developer Portal integration** и защищённые Code signing identities / Secret environment variables. В YAML хранить только ссылку на интеграцию; её точное reference name проверить в Codemagic. Не предполагать, что старое `app_store_connect: codemagic` корректно для нового KMP.
- Apple ID пароль для нормального API-key signing не нужен. Не отправлять `.p8`, `.p12`, пароли сертификатов, токены или файлы резервных паролей в GitHub, issue, чат, артефакты или логи. Не включать `set -x`, `env`, `printenv` рядом с секретами.
- Если ключ отозван/недействителен: владелец входит в Apple, проверяет соглашения/роль, затем разрешает создание/замену отдельного ключа и вводит его прямо в защищённую интеграцию Codemagic. Не отключать защиту Apple ради автоматизации.
- Эта публикация не является резервной копией всех личных паролей/Android signing keys. Облачная iOS-интеграция уже хранится в Codemagic; для остальных секретов нужен личный менеджер паролей владельца. Не извлекать браузерные пароли/куки.

## Перед первым TestFlight

`ios-ipa-kmp` и `scripts/build-kmp-ios-ipa.sh` сейчас намеренно отключают подпись; добавления одного `ios_signing` недостаточно.

1. Проверить совместимость Kotlin/Native, SKIE и Xcode/SDK. Текущий Kotlin 2.1.21 исторический; `xcode: latest` может потребовать отдельного обновления стека. Не выдавать старый совместимый Xcode за допустимый для нынешней загрузки Apple.
2. После успешной диагностики создать отдельный Release archive/export workflow с явной подписью и существующей карточкой Apple. Сохранить unsigned smoke отдельно.
3. Исправить схему версий: текущий KMP Info.plist **0.1.0 / 1** не подходит для обновления опубликованной **1.0.3**. Перед загрузкой выбрать следующую маркетинговую версию и получать уникальный build number по актуальным данным App Store Connect. Не просто многократно менять `1` вручную.
4. Проверить миграцию Flutter → KMP на копии реальных/синтетических данных. Обновление с тем же Bundle ID не должно открывать пустую библиотеку и терять медиа.
5. Независимо проверить приложение на iPhone; только после этого TestFlight для бета-тестеров. Production-публикация требует отдельного согласия владельца и приёмки.
